# Spec ch. 0 — Glossary: the ubiquitous language

*Satisfies: family principle 1 (via P3's naming discipline); method requirement (Prompt 2,
Task B). Every domain term used normatively in chapters 1–9 is defined here, once. Chapters
use these terms exactly; the **aliases to avoid** are closed doors. Class names shown are
the canonical `PGR` spellings the implementation must use (D-11).*

| Term | Meaning | Aliases to avoid |
|---|---|---|
| **check** | Anything runnable by the gate that answers one verdict for one registration: a lint rule bound to the production packages, the layer-map check, one tests-role package's suites, a meta-rule. Contract: the check **protocol** (`run`, `kind`, `canFix`) — `PGRCheck` is its optional skeleton, in `-SDK` (D-53). | "test" (reserve for SUnit tests), "rule" (only lint checks are rules), "validation" |
| **check kind** | The open classification of checks a kit ships, carried on each registration as a `Symbol`. The coding kit's kinds: `#lint`, `#architecture`, `#behavioral` (the former `#sweep` kind was withdrawn, D-37). The core treats kinds as opaque labels (R-04). | "check type", "category" |
| **registration** | One member of the registry: a unique **registration name**, a kind, and either a resolved check or the reason it is missing (the former `scope` field left with the two-scope model, D-51). Class: `PGRRegistration`. | "entry", "activation" |
| **registration name** | The registration's unique, deterministic identifier, `<kind>/<discriminator>` (e.g. `lint/PGRNoIsNilIfTrueRule`, `behavioral/Phi-Guardrails-Toy-Tests`). Duplicate names are a configuration error. | "id", "key" |
| **registry** | The explicit, inspectable collection of registrations one gate run enforces, built per run from the configuration artifact **alone** (D-51 — no shipped defaults, no merge). Class: `PGRRegistry`. Never global state (R-35): constructed, passed, discarded. | "rule set", "singleton registry" |
| **scope** *(withdrawn, D-51)* | Former registration-provenance term (global vs project). One scope remains: the file. Distinct from **scope law** (package coverage, D-25), which stands unchanged. | — |
| **global catalog** *(withdrawn, D-51)* | Former shipped default registrations (`globalCatalogSTON`, D-18). Kits ship no catalog; see **recommended block**. | — |
| **recommended block** | A kit's documented, pre-written block template, composed into `guardrails.ston` at authoring time — by hand or by the init command. A template, not a mechanism: nothing runs unless the project's file names it (D-51). | "defaults", "global catalog" |
| **configuration artifact** | The client's `guardrails.ston` (D-16), read from the **explicit path the caller passes** — no repo-root convention, no working-directory default (D-45); in-repo at the root is the recommended default for projects that own their config. Pure-data STON declaring schema version, project name, baseline, roles (matchers), and the ordered per-kit **blocks** (D-51) — **the complete statement of what runs**. Parsed into `PGRConfiguration`. | "config", "manifest", "settings" |
| **schema version** | The artifact's `#schemaVersion` (Integer). The gate reads its own version and older ones and **refuses a newer one** with a clear configuration error rather than misinterpreting it (D-45) — tool and target repos version independently. | "format version", "v" |
| **source root** | The `#src` path the dead-src check walks, interpreted relative to the config file's own directory (D-45); optional — required only by a registered check that consumes it. | "working directory", "project dir" |
| **caller** | Whoever invokes the gate: a developer in a Playground, a CI job, a script, an agent or harness, another tool. **No caller is privileged and none is required** (D-45); the project under check is the gate's *subject*, never its operator. One of the four audiences (D-48). | "runner" (see reference runner), "driver" |
| **audience** | One of the five roles the framework promises a surface to: gate caller, fix invoker (consumer side, split by mutation rights), check author, kit author (producer side, nested), config author (schema, not code). Four are code **SDKs**; the config author's surface is the artifact schema + the init tool (ch. 0 §0.3; D-48/D-49 recomposed by D-53). | "user", "persona" |
| **public surface** | The exact protocol promised to an audience (ch. 0 §0.3) — since D-53, packaged as four **SDKs** plus the config-author schema. The M1 freeze binds public-surface members only; the report's printed text is human-facing, not an API — the machine contract is the exit code and the artifact schema (D-48). | "API" (bare), "interface" |
| **SDK** | Two related senses (D-53): (1) the boundary package `Phi-Guardrails-SDK` — protocol declarations, the two skeletons, the frozen vocabulary; (2) one of the four audience surfaces (Check-author, Kit-author — nested; Gate-caller, Fix-invoker — split by mutation rights), each **complete** (everything its audience needs) and **minimal** (nothing else). | "library", "client lib" |
| **protocol** | Two senses, kept apart (D-53): (1) a **contract** — a message set plus behavioral expectations (the check and kit protocols); conformance to it, not ancestry, is what registration requires, validated at registry construction; (2) a Pharo **browser method category** — contract methods sit in one named for their surface (human-visible convention, unenforced). | "interface" (Pharo has none), bare "category" |
| **skeleton** | An optional abstract superclass (`PGRCheck`, `PGRKit`) shipping documentation, `subclassResponsibility` markers, and helpers — a convenience for conforming, never a requirement (D-53). Abstract classes, not traits (B-03's attribution subtleties are live). | "base class" (implies required ancestry) |
| **vocabulary** | The frozen value classes of the boundary, in `-SDK`: `PGRVerdict`, `PGRFinding`, `PGRRegistrationSpec` (D-54 — what a kit answers; the engine wraps it into its internal `PGRRegistration`), `PGRConfigurationError`, the fix-invocation errors. Crossing SDKs by design (constructors producer-side, readers consumer-side) — the boundary's shared language, not coupling (D-53). | "DTOs", "model classes" |
| **capability** | A protocol feature a check *declares* rather than inherits: `canFix` (skeleton default false) — a fixing check overrides it and produces a previewable change (D-53). | "feature flag", "trait" |
| **published stanza** | ≡ **recommended block** (one concept, D-53): the kit's starter block, **single-sourced on the kit class as `recommendedBlock`** (D-54) — the init tool composes from it, docs quote it, and P-STANZA-VALID keeps it true (every check it names must register and conform). | "default config" |
| **internal** | Everything not named in a public surface — specified for implementation, changeable without notice, never a compatibility promise (D-48). | "private" (Pharo has no enforcement; this is a contract term) |
| **reference runner** | The convenience image-assembly + invocation shipped with phi-guardrails (`guardrails.sh` and its recipe, §7.3) — one caller among many; it must not re-privilege any caller (D-45 ruling 4). | "the CI integration", "launcher" |
| **adapter / ci-tests / no-self-sweep** *(withdrawn, D-45)* | Former machinery of the operator model: the CI adapter TestCase (D-10), the `Phi-Guardrails-CI-Tests` exempt package, and D-23's no-self-sweep rule — all retired by the invocation model; only §8.1's residual caveat survives. | — |
| **kit block** *(formerly* section*, D-51)* | One member of the `#kits` array: a self-contained map naming its kit (`#kit`) and carrying that kit's entire configuration (e.g. `#lintRules`, `#layerMap`) — opaque to the core, strictly validated by the kit. Registration keys list check entries; **parameter keys** (`#layerMap`) carry data registered checks consume. | "section", "stanza" |
| **kit** | A domain-specific package family plugging in **against the SDK, never the engine** (D-53): check classes, their engines, a published stanza, a block schema, fixture pairs (R-40 as amended by D-51/D-53). Contract: the kit **protocol** (`kitName`, `registrationsFrom:productionPackages:testsPackages:`) — `PGRKit` is its optional skeleton; first kit: `PGRCodingKit`. | "plugin", "module", "domain" |
| **engine** | Kit-internal machinery a check drives (Renraku checker, the rewrite engine, the SUnit runner, reflective queries). Engines never appear in core vocabulary (R-04). | "backend", "runner" (as a noun for classes) |
| **gate** | The plain object that runs a registry and aggregates verdicts into a report; headless-invocable, exits nonzero on any non-green verdict (P4, P6). Class: `PGRGate`. | "pipeline", "build check", "CI" (CI *invokes* the gate) |
| **verdict** | The outcome of one registration in one run: status `#green`, `#red`, `#missing`, or `#skipped`, plus findings, advisories, and timing. Class: `PGRVerdict`. | "result", "status" (status is the verdict's field) |
| **green / red / missing / skipped** | Verdict statuses: green = ran, no blocking finding; red = ran with blocking findings (or the check errored, D-21); missing = the registration could not resolve (class not loaded, tests-role package without tests, empty tests-role expansion, required parameter section absent — R-24); skipped = registered but not run (only in aborted runs, D-21). Everything non-green fails the gate. | "passed/failed" (SUnit vocabulary), "warning" (that is a severity) |
| **finding** | One blocking violation inside a verdict: target (printed precisely, R-20), message, and the rule's rationale where one exists. Class: `PGRFinding`. | "criticism", "issue", "offense" |
| **advisory** | A non-blocking finding: a critique from a lint rule whose severity is below `#error` (D-03), or the layer-map check's line naming its `#unlayered` packages (D-35). Reported, never fails the gate. | "warning" (severity name, not finding name), "info" |
| **report** | All verdicts of one gate run plus the aggregate: clean or not, exit code, rendering. Class: `PGRReport`. | "summary", "log" |
| **severity** | A lint rule's declared weight: `#error`, `#warning`, or `#information` (class-side `severity`, D-15). Only `#error` critiques block (D-03). Non-lint checks have no severity — they always block. | "priority", "level" |
| **rule** | A **lint** check: a Renraku rule class (a descendant of the Renraku rule base, ch. 2 §2.2) registered by name in `#lintRules`. Where a safe rewrite exists it is a **rewrite rule** and carries its autofix (P1). | "critic", "lint" (as a noun), "checker" |
| **critique** | Renraku's own finding object, produced by the engine. The word appears only in chapter 2 (and 3) at the Renraku boundary; every other chapter says finding/advisory. | using "critique" outside the engine boundary |
| **meta-rule** | A test-discipline check registered in `#metaRules`, judging the *test suites* rather than production code. v1: `PGRNoSkippedTestsMetaRule` (D-08). | "policy", "test rule" |
| **sweep** *(withdrawn, D-37)* | Former check kind (`#sweeps` section, `PGRSecretsLeakCheck`, D-09) — withdrawn from scope at Gate 2. "Swept" survives only as the informal verb for *targeted by registered checks* (as in "never swept" for exempt-role packages). | — |
| **secret pattern** *(withdrawn, D-37)* | Former term of the withdrawn secrets-leak check; no `#secretPatterns` section exists. | — |
| **baseline** | The client's `BaselineOf` subclass — the product's only package *inventory*; the artifact's `#baseline` names it, and the config's role matchers assign over exactly the packages it defines (D-25 as amended by D-45). | "package list", "manifest" |
| **run mode** | One of the three moments checks run (D-25): **edit** (touched methods, as the agent writes), **chunk** (work-order handoff), **CI** (full registry from the committed artifact). Only CI produces the verdict of record; the others are informative. | "tier", "stage", "advisory run" |
| **verdict of record** | The one verdict that gates the build: the CI run mode's report, computed from the committed artifact over the baseline-derived packages (P6, R-08). | "official result", "final verdict" |
| **scope law** | D-25's totality rule: the role groups must exist, be pairwise disjoint, and jointly cover every package the baseline defines — violation is a configuration error. The compound terms *scope law* and *package scope* concern code coverage (D-25) and are distinct from bare **scope** (registration provenance) above. | bare "scope" for code coverage |
| **group role** | The artifact's `#roles` assignment of packages to `#production` (targeted by lint and architecture checks), `#tests` (behavioral suites), or `#exempt` (never targeted by any check) — by **matchers**: baseline group names (a convenience), package names, or full-match patterns (D-45). Assignment lives in the config; the inventory is the baseline's; after expansion the roles are disjoint and jointly total over the baseline's packages — the scope law (D-25). | "category", "tag" |
| **AST pattern** | The meta-variable match expression a rule declares (e.g. `` `@x isNil ifTrue: [`.@block] ``); a rewrite rule pairs it with a replacement. The one surviving technical sense of "pattern" (see collision note below). | bare "pattern" at first mention, "match string" |
| **autofix** | The safe rewrite a rewrite rule carries (AST pattern → replacement). Applied only by the fix command, never by the gate (R-12). | "auto-correct", "quick fix" |
| **fix command** | The explicit, preview-first applier of one rule's autofix to a stated target (D-06). `PGRFixCommand` is the coding kit's *implementation* of the SDK's generic fix-invocation protocol (construct → preview → apply → changes, staleness required — D-53). Invoker may be human or agent; the preview diff is always emitted before apply. | "fixer", "--fix mode" |
| **preview** | The before/after source diff the fix command emits for every prospective change, mandatorily, before any apply (D-06). | "dry run" |
| **layer map** | The client-declared architecture data in `#layerMap`: named layers (disjoint package sets), allowed directed layer dependencies, and the declared `#unlayered` remainder — layers + `#unlayered` jointly total over the production role (D-35). Consumed by the layer-map check. | "dependency graph", "arch config" |
| **layer** | One named entry of the layer map: a name plus the packages it contains. | "tier", "level" |
| **behavioral suite** | The SUnit suites of one tests-role package, run once per gate run and judged as one registration (D-25). | "test run" |
| **fixture pair** | The two committed fixtures every shipped check needs (R-37): a **bad fixture** the check must flag and a **good fixture** it must stay silent on, each exercised by a named test. | "sample", "example" (reserved for `<example>` pragma methods) |
| **toy client** | The in-repo demonstration client `Phi-Guardrails-Toy-*` (D-12): a mini layered app with planted violations of every v1 check, loaded only by the Toy baseline group. | "demo app", "sample project" |
| **planted violation** | A deliberate, committed defect in the toy client that exactly one v1 check must catch (R-32/R-43/R-44). | "seeded bug" |
| **promotion** | Including a client check in a kit's **recommended block** (D-51): move the class into the shipped package, fixtures along, and add the entry to the documented template so future init drafts carry it — documentation, not mechanism; existing adopters change nothing until they edit their own file (D-07 as amended). | "upstreaming" |
| **self-hosting** | This repo polices itself: its own `guardrails.ston` puts the framework's own baseline under every shipped check from the first rule onward (R-38). | "dogfooding" (colloquial; fine in prose, not in code) |
| **blocking** | Property of a finding/verdict that fails the gate. Blocking = any non-green verdict; within lint, only `#error` critiques produce findings (others produce advisories). | "fatal", "hard fail" |
| **configuration error** | A defect in the artifact itself (unknown key, malformed section, duplicate registration name, undeclared kit class): the gate run fails outright with a nonzero exit *before* producing a report (D-16). Class: `PGRConfigurationError`. | "invalid config warning" |

**Resolved term collisions.** 
* *pattern* → the qualified term **AST pattern** is mandatory at first mention in any section and wherever the referent could be ambiguous — after that, an anaphoric bare "the pattern" within the same section is fine. (The two former competing senses are gone: *secret pattern* withdrew with its check, D-37; *test-package pattern* was retired by D-25 — behavioral targets are tests-role packages now. `#exemptNamePatterns` regexes are always named in full.) 
* *test* → SUnit test methods only; gate-runnable things are **checks**. 
* *warning* → the `#warning` severity only; a reported non-blocking item is an **advisory**. 
* *registry* → the per-run explicit object; the family principle "no registries" forbids *global/singleton* registries, which `PGRRegistry` is not (R-35, reconciled in D-01).
