# Spec ch. 9 — Testing: named properties for every law

*Satisfies: R-37, R-38, R-39 (process trace), and the method's spec-quality bar: every
binding principle/invariant restated as ≥1 named, testable property. Item 9 of the
pack's §8 outline (added at Gate 2 — originally a spec-agent addition under the
method's quality bar; the owner later amended the outline to carry it). Test classes live in the mirroring
`Phi-Guardrails-Tests-*` packages — all of them, with no exception clause: the
`Phi-Guardrails-CI-Tests` carve-out is retired by D-45 and the toy demo test lives in
the tests-role `Phi-Guardrails-Tests-Toy` (D-46), so the no-skips meta-rule now sweeps
every test class the framework owns. Every property below names the suite that proves
it, and every one is decidable — it fails or it doesn't.*

## 9.3 Conventions binding all tests

Tests-first per work order (constitution §3). Fixture classes never sit in
**production-role** packages — the roles that lint and architecture checks
target (§3.2, D-25). Fixtures without red tests (lint bad code, architecture
mini-packages) sit beside their tests in the mirroring tests-role package, where they
are inert (a behavioral run executes only `TestCase` classes); fixtures that must
contain red, skipped, or expected-failure tests live only under the exempt-role
`Phi-Coding-Kit-Fixtures-*` (§5.5, D-22). No test
class in `Phi-Guardrails-Tests-*` uses `skip`/`expectedFailures` (constitution §3),
enforced machine-side by the self-hosted no-skips meta-rule (the framework's tests role
covers both tests families — `Phi-Guardrails-Tests-.*` and `Phi-Coding-Kit-Tests-.*`,
D-57). The `CI-Tests` conventions that stood here — the
reviewer-enforced no-skips carve-out and the timeout-as-de-facto-check argument for
gate-driving-test placement — are **retired with the package** (D-45); what remains is
§8.1's one-sentence residual caveat: do not invoke the gate on this repo's own config
from inside this repo's swept tests. The verify command
(`test --fail-on-failure "(Phi-Guardrails|Phi-Coding-Kit)-Tests-.*"` — alternation
spelling ⟨verify⟩, D-57) is the acceptance instrument for
every chunk; the self-hosted gate — invoked directly, §7.4 step 2 — is the second
instrument from M1 onward.
